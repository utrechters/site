# CLAUDE.md — utrechters

Volunteer-run website for a Utrecht-based expat meetup community. Intentionally small and simple — keep it that way.

## Stack

| Tool            | Version                                   |
| --------------- | ----------------------------------------- |
| SvelteKit       | ^2.50                                     |
| Svelte          | ^5.50 (runes mode)                        |
| Vite            | ^6                                        |
| Tailwind CSS    | v4 (via `@tailwindcss/vite`)              |
| TypeScript      | ^5, strict mode                           |

## Architecture

```
messages/                    # Paraglide UI string files (en/nl/hu)
project.inlang/
  settings.json              # Inlang project: language tags + message format path
scripts/
  validate-data.js           # Data validation script (ajv)
src/
  app.css                    # Tailwind import + custom CSS variables (theme lives here)
  app.html                   # %paraglide.lang% placeholder for language injection
  hooks.server.ts            # Paraglide handle + lang-placeholder injection
  hooks.ts                   # Paraglide reroute (strips /nl/ /hu/ prefix for SvelteKit)
  components/
    atoms/                   # Single-purpose: eventBox, link, svgIcon
    molecules/               # Composed: navigation, altNav
    organisms/               # Layout-level: header, footer
  lib/
    inView.ts                # Intersection Observer utility
    paraglide/               # Generated by Vite plugin — DO NOT EDIT
      runtime.js             # getLocale(), setLocale(), etc.
      messages.js            # Compiled message functions (m.setup_h1(), etc.)
      adapter.js             # SvelteKit handle + reroute hooks
    data/
      countries.json         # [{ code, name, region, flag }] — CH, NL, RO
      countries.schema.json  # JSON Schema for countries
      item.schema.json       # JSON Schema for items (id pattern, category enum, intensity 1–3)
      items/
        ch.json              # 15 Swiss items
        ro.json              # 15 Romanian items
        nl.json              # 15 Dutch items
      i18n/
        en/{ch,ro,nl}.json   # English item labels (source language, always required)
        nl/{ch,ro,nl}.json   # Dutch item labels
        hu/{ch,ro,nl}.json   # Hungarian item labels
    engine/
      types.ts               # Item, Round, Profile, Phase, Side, Category
      pure.ts                # buildRoundQueue, computeProfile, shuffle — pure, no Svelte
      game.svelte.ts         # Svelte 5 runes GameState class + singleton `game` export
      pure.test.ts           # Vitest tests (21 tests)
  routes/
    +layout.svelte           # Root layout
    +page.server.ts          # Server-side event data fetch (NOT +page.ts)
    +page.svelte             # Home page (hero, about, guidelines, contact)
    expat-bivalent/
      +page.server.ts        # Validates ?a=&b=&score= URL params for shared results
      +page.svelte           # Game UI: setup → playing → result (paraglide strings)
    privacy/
      +page.svelte           # Privacy policy
```

- Component filenames: camelCase (e.g. `eventBox.svelte`)
- Data loading: always server-side in `+page.server.ts`, never in `+page.ts`
- `src/lib/paraglide/` is generated — never edit it directly; re-runs on every build
- In-page navigation uses hash anchors (`#about`, `#rules`, `#contact`)

## Svelte 5 — Runes Only

Always use runes. Never use Svelte 4 legacy syntax.

```svelte
<!-- Props -->
let { title, count = 0 }: { title: string; count?: number } = $props()

<!-- State -->
let open = $state(false)

<!-- Derived -->
let doubled = $derived(count * 2)

<!-- Effects -->
$effect(() => { console.log(open) })

<!-- Events -->
<button onclick={() => (open = !open)}>toggle</button>

<!-- Children (not slots) -->
{@render children()}
```

- No `export let`, no `$:`, no `on:event`, no `createEventDispatcher`
- No Svelte stores — use `$state` / `$derived` instead
- No `<slot>` — use snippet syntax with `{@render}`
- `.svelte.ts` files: ESLint ignores them (rune syntax); `svelte-check` covers them

## Tailwind CSS v4

- Import: `@import "tailwindcss"` in `app.css` — no `@tailwind` directives
- Theme tokens are CSS variables in `app.css`, not in a config file
- No `tailwind.config.js` changes needed for new colors — add variables to `app.css`

### Custom color palette

| Variable                           | Usage                            |
| ---------------------------------- | -------------------------------- |
| `--color-cream` (`#faf7f2`)        | Page background                  |
| `--color-warm` (`#f0ebe4`)         | Borders, subtle backgrounds      |
| `--color-surface` (`#1e1c1a`)      | Dark sections background         |
| `--color-accent` (`#00816a`)       | Primary interactive color (teal) |
| `--color-accent-light` (`#e6f4f0`) | Light accent backgrounds         |
| `--color-highlight` (`#e8d5b7`)    | Warm beige highlights            |
| `--color-text` (`#2d2a26`)         | Body text                        |
| `--color-text-muted` (`#6b6560`)   | Secondary text (cream bg only)   |

Use these semantic names — avoid raw Tailwind color utilities like `text-green-700`.

**Contrast note:** `text-text-muted` (#6b6560) fails WCAG AA on `bg-surface` (#1e1c1a). On dark backgrounds use `text-white/50` instead.

## Design Guidelines

- **Mobile-first**: write base styles for mobile, layer `sm:` / `md:` on top
- **Animations**: always wrap with `motion-safe:` — respect user preferences
- **No inline styles** — Tailwind classes only. Exception: dynamic percentage values for progress bars must use `style:width="{pct}%"` (no Tailwind equivalent)
- **Layouts**: CSS Grid for multi-column (`grid sm:grid-cols-2`)
- **Accessibility**: semantic HTML, proper heading hierarchy (`h1` → `h2` → ...), ARIA labels where needed
- **External links**: always `target="_blank" rel="noreferrer"`
- `@tailwindcss/typography` is available for rich text sections

## Dependencies Philosophy

This site has minimal dependencies by design. Before adding any package:

1. Can this be done in ~10 lines of Svelte or TypeScript? If yes, do that.
2. Is it a dev-only tool (linting, typing)? Fine to add.
3. Is it a runtime UI library or state manager? Probably not — ask first.

## Events API

Server-side only — see [src/routes/+page.server.ts](src/routes/+page.server.ts).

- Endpoint configured via `VITE_EVENT_API` env var (default: `http://localhost:3001`)
- Returns upcoming Tuesday and Friday meetup events
- Shape: `{ Tuesday: { link: string, date: Date | null }, Friday: { ... } }`
- Caching is handled by SvelteKit's server load lifecycle — no manual cache logic needed

## i18n — Paraglide

Two separate i18n layers:

### UI chrome (Paraglide)

- Package: `@inlang/paraglide-sveltekit@^1.0.0-beta` with `strategy: ["url", "cookie", "baseLocale"]`
- Languages: `en` (default, no URL prefix), `nl` (`/nl/route`), `hu` (`/hu/route`)
- Message files: `messages/{en,nl,hu}.json` — key/value JSON
- Generated runtime: `src/lib/paraglide/` (auto-generated on build, gitignored content)
- Import in components: `import * as m from "$lib/paraglide/messages.js"`
- Current locale: `import { getLocale } from "$lib/paraglide/runtime.js"`
- The beta adapter doesn't inject `%paraglide.lang%` — `hooks.server.ts` does it via `transformPageChunk`

### Item content strings (flat JSON, not Paraglide)

- Lives in `src/lib/data/i18n/<lang>/<code>.json`
- Fallback chain in the game page: `lang[country][id]` → `en[country][id]` → raw id
- **Why not Paraglide?** Item corpus grows via community PRs; compile-time messages don't suit an append-only content dataset

## Expat Bivalent — game module

A "would you rather" identity game for expats at `/expat-bivalent`. Pick two countries, choose between paired cultural items across 15 rounds, get a shareable percentage split. Pure client-side; no backend.

### How the engine works

```
src/lib/engine/
  types.ts     Item · Round · Profile · Phase · Side · Category
  pure.ts      buildRoundQueue(codeA, itemsA, codeB, itemsB) → Round[]
               computeProfile(votesA, votesB) → { pctA, pctB }
               ROUND_COUNT = 15 · WILDCARD_INTERVAL = 5
  game.svelte.ts  class GameState { phase, currentRound, profile, ... }
               export const game = new GameState()  ← module singleton
```

- Rounds: mostly same-category pairs; every 5th round is a wildcard (intensity-3 from different categories)
- State: Svelte 5 `$state` class fields on the singleton; no localStorage
- URL: result encoded as `?a=CH&b=RO&score=60` via `replaceState` from `$app/navigation`

### Item data format

```json
{ "id": "ch-fondue", "category": "food", "intensity": 1 }
```

- `id`: two-letter country prefix + slug, e.g. `ch-fondue` lives only in `ch.json`
- `category`: `food | place | icon | transport | trait | economics | misc`
- `intensity`: `1` (fun) · `2` (notable) · `3` (identity-defining; used for wildcards)
- Schema: `src/lib/data/item.schema.json` (draft-07, `ajv`-validated)

Adding a country: add `items/<code>.json`, `i18n/en/<code>.json`, import both in `game.svelte.ts`'s `ITEM_REGISTRY` and in the page's `ITEM_I18N` map. Update `SUPPORTED_CODES` export.

### URL sharing + OG

- Result URL: `/expat-bivalent?a=CH&b=RO&score=60`
- Visiting a result URL skips the game and shows the result card directly (server load validates params, page initializes from `data.shared`)
- OG image: static `/utrechters.png` for now — **TODO: generate dynamic OG image from result card**

### Priorities (when making trade-offs)

1. Easy community contribution (the data schema is the product)
2. Cultural accuracy / not-offensive categorisation
3. Replayability
